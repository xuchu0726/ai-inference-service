# Redis Stream worker crash reclaim E2E

## 验证目标

验证 worker 在任务已进入 running 状态后异常终止时，任务保留在 Redis PEL，
replacement worker 能通过 XAUTOCLAIM 接管并完成任务。

## 运行配置

- Redis prefix: ai-inference:week4:crash-reclaim-v2
- Consumer group: crash-reclaim-workers-v2
- Crash worker: self-kill-worker-v2
- Replacement worker: replacement-worker-v2
- Backend: mock
- Reclaim idle threshold: 100 ms（仅本次故障注入验证覆盖；生产默认值保持不变）
- Git commit: 8365b67c56ce17aa430adf6865ce841f59c0f32f

## 故障注入前提

Crash worker 日志出现 GENERATE_CALLBACK_REACHED_AFTER_RUNNING，说明任务已经：
1. 被 consumer group 投递；
2. 成功写入 running 状态；
3. 已进入 generate_text 回调；
4. 随后由回调内 SIGKILL 强制终止。
